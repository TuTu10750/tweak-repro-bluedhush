# v13.2-P1 · 虚拟定位真正落地 + 与原版能力对照

> 触发：用户反馈"虚拟定位完全没有任何作用""净化看不见效果"。
> 这一版不解释、不猜，先做两件事：**把定位打到宿主真正的入口**，**把原版能力列清楚**。

---

## 1. 上一版为什么"开关开着但什么都不做"

`REALoadFakeLocation()` 原文逻辑：

```objc
if (defaults 里有 rea_fake_location) { 解析; gREAHasFakeCoord = YES; }
```

没在地图里选过点 → 坐标变量一直是空的 → `CLLocationManager -location` 的 hook 走的是"没有假坐标"分支 → 直接调原实现。
**开关是开的，钩子也装了，但取不到假坐标，等于空转。** 这就是"完全没作用"的代码级原因。

v13.1-P1 已改成：没有配置就落内置坐标 `39.908722,116.397499`（北京），`gREAHasFakeCoord` 恒为 YES。

---

## 2. 但只改这个还不够：宿主的真入口有两处

`CLLocationManager` / `CLLocation` 的 hook 只挡住"谁问坐标"，挡不住下面两条真实路径：

| 路径 | 宿主方法（实测类型编码） | 后果 |
|---|---|---|
| 本地定位落地 | `BDLocationService -locationManager:didUpdateLocations:` `v32@0:8@16@24` | 它是 CLLocationManager 的 delegate，拿到的 `locations` 是**真坐标**；身边列表、地图、距离计算读的是它 |
| 服务端位置上传 | `BDSettingShadowRequest -uploadShadowLocation:longitude:latitude:isOpen:shadowId:success:failed:` `v68@0:8@16d24d32B40q44@?52@?60` | 这是**影子位置**：传上去之后，别人首页看到的位置就是它。原版"追踪/坐标卡片"能生效，靠的就是这条 |

v13.2-P1 新增 `REAInstallLocationHooks()`，两个都换掉：

```objc
p_locDidUpdate  = REASwap(BDLocationService, "locationManager:didUpdateLocations:", rea_locDidUpdate);
p_shadowUpload  = REASwap(BDSettingShadowRequest,
                          "uploadShadowLocation:longitude:latitude:isOpen:shadowId:success:failed:",
                          rea_shadowUpload);
```

日志（这两条就是"有没有真落地"的判据）：

```
[Loc] BDLocationService didUpdateLocations hook=ok
[Loc] BDSettingShadowRequest uploadShadowLocation hook=ok
[Loc] BDLocationService didUpdateLocations：1 个真坐标 → 换成 39.908722,116.397499（第 1 次）
[Loc] 影子位置上传：31.230416,121.473701 → 39.908722,116.397499（服务端位置，别人看到的就是这个）
```

反过来：如果日志里 `hook=miss`，说明这个版本的 App 改了类名，需要重新对 host_index 找 owner；
如果 `hook=ok` 但一条命中都没有，说明这条业务路径没被触发（冷启后要进身边页 / 地图页才会走）。

## 3. 面板里的「虚拟定位」现在开地图窗口

不再是三个输入框。新增 `REALoc.xm`（编辑/拾取/保存一整个窗口），方法名沿用参考件的 `hushLoc*` 前缀，方便逐条对照：

| 能力 | 参考件标识符 | 我们的实现 |
|---|---|---|
| 长按地图取点 | `hushLocMapLongPress` / `hushLocLongPress` | `handleLongPress:` |
| 单点取点 | `hushLocTap` | `handleTap:` |
| 双击放大取点 | `hushLocDoubleTap` | `handleDoubleTap:` |
| 准星拾取（拖地图不挪针） | `hushLocateHere` / `hushLocAimIfPossible` | `locateHere` / `aimIfPossible` |
| 撤销回原位 | `hushRedo` / `hushLocClearPick` | `redo` / `clearPick` |
| 地图类型切换 | `hushLocToggleMapType` | `toggleMapType` |
| 保存点列表 | `hushLocSaveItems` / `hushLocHistoryPicked` | `saveItems` / `historyPicked`（存 `rea_loc_history`，最多 20 条） |
| 反向地理编码 | `hushLocConfirm` | `geoReverse:`（MKReverseGeocodingRequest） |
| 保存并通知宿主刷新 | `hushLocActionSegment` | `saveAndExit` → 调 `REAPushFakeLocationToHost()` |

窗口承载优先用 `REAWindow`（`UIWindowLevelNormal+1`），不抢宿主的 key window —— 这是 v13.0-P0 修卡启动图时定下的规矩。

## 4. 与原版（BluedHush_5.19.dylib）能力对照

从参考件里提取到 **188 个 `hush*` 标识符**，按功能归类后对照如下。这张表就是"1:1 还差多少"的账本。

| # | 能力块 | 原版证据（标识符/键） | 我们当前 | 差距 |
|---|---|---|---|---|
| 1 | 定位拾取窗口 | `hushLoc*` 41 条、`hush_loc_*` 键 20 个 | **v13.2 已实现** | 无（缺"探索地图高清头像" `hush_map_avatar_hd`） |
| 2 | 定位真落地 | `hush_loc_tracking`、`hush_loc_master_timestamp` | **v13.2 已实现**（两处宿主入口） | 无 |
| 3 | 附近标记 | `hush_nearby_marks`、`hush_nearby_sig_cache_v1` | 无 | 需先有榜单位置缓存，P3 |
| 4 | 追踪卡片 | `HushTrackMapCardVC`、`hushTrackButtonTapped`、`hush_track_card_*` 8 个 | 无 | 只差 UI；底层 `uploadShadowLocation` 已接通 |
| 5 | 追踪目标/模板 | `hush_track_target`、`hush_track_template` | 无 | P3 |
| 6 | 撤回拦截 | `hush_recall_intercepted` / `pending` / `snapshot` | **已接**（GJIM* 13 个 hook + 消息模型 4 个） | 缺"定时撤回"`hush_scheduled_recall` |
| 7 | 聊天备份/备注 | `hush_chat_backup`、`hush_chat_notes_v1` | 无 | P4 |
| 8 | 消失消息 | `hush_vanished`、`hushvan_*` 4 个 | 无 | P4 |
| 9 | 相册/图库备份 | `hush_album_*` 8 个、`hush_gallery_*` 5 个、`hushgal_*` 7 个 | 无 | 量最大，P4 |
| 10 | 访客痕迹 | `hush_spy_visitors`、`hush_visit_clear_lp`、`hush_rel_*` | 部分（`RecentlyVisitorViewController -p_needToBuyVip`） | P3 |
| 11 | 风控名单 | `hush_risk_users`、`hushrisk_name` | 无 | P4 |
| 12 | 设备伪装 | `hush_fake_device_id` | 无 | P4 |
| 13 | 闪照 | `hush_flash_photo`、`hush_flash_converted`、`hush_auto_burn_mem_v2` | **已接**（`flash_photo` / `flash_text`） | 缺"自动焚毁内存版" |
| 14 | 净化 | 原版没有独立净化引擎（它主打定位/备份） | **33 选择子锚点 + 53 视图规则** | 我们反而更强，弱项是类名子串对不上真广告类 |

**结论**：定位这一块 v13.2 追平到"能真正落地"；追踪卡片只差 UI；相册/聊天备份/风控是原版体量最大的部分，需要单独排期，不能靠一次改动堆出来。

## 5. 现在每个开关打什么日志（可自查）

| 开关 | 命中日志 |
|---|---|
| 虚拟定位 | `[Loc] ... 换成 lat,lng` / `[Loc] 影子位置上传 ...` |
| 防撤回 | `[Purify] 拦截 GJIMMessageModel -recallType` 等（REAHOOK 36 条各自一行） |
| 反截屏 | `[Purify] 拦截 BDMessageViewController -p_screenshotTip` |
| 净化（每个 key） | `[Purify] 命中 类名 -选择子 → key` 或 `[Purify] 视图净化 类名` |
| 净化总览 | `[Purify] 锚点层：当前生效 key=N/M（视图层另有 53 条规则…）` |
| 开屏 | `[Purify] 档位：… L1(splash_ad)=off`（构造成员期强制关） |

判断"钩子真的接上了"看三行：`pass[ctor] ok=… miss=0`、`[SettingsEntry]`/`[Purify] 锚点层`、`[Loc] … hook=ok`。

## 6. 装法 / 回滚

1. 解压 `BluedHushREA-v13.2-P1.zip`。
2. 用 `BluedHushREA.dylib` 替换 App 里原来那个（同名同路径），plist 不用换。
3. 回滚：换回 `dist/v12/BluedHushREA.dylib`，并删掉 `rea_loc_*` 三个 defaults key。

已知遗留：
- 追踪卡片 UI 未做（底层已通）；
- 相册/聊天备份未做；
- `purify_splash_ad` 的脏值需要手动关一次（构造期会强制写 NO，但要等下次启动才彻底清）。
