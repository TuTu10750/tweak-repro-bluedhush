# v13.0-P0（build tag `v13.0-P0`）

> 一句话：**把 v12 里会咬人的两件事（净化引擎、设置页注入）改成出厂关，把"到底卡在哪"变成日志里的一行结论。**

## 1. 为什么做这一版

v12 真机日志（`D:\DeepSeek\hush\BluedHushREA.log`，3,187 行 / 22 次启动）给出了三条硬事实：

| 事实 | 日志原文 |
|---|---|
| 19 条开屏锚点里只有 **1 条**真正被调用 | `[Purify] 拦截 AppDelegateModel -getSplashAdForColdLaunch → purify_splash_ad`（4 次）；`isNeedShowSplashAd` / `showSplashAd:` / `assembleSplashContainerView:` / `showInWindow:` / 全部 `finished` = **0 次** |
| 全 App 长时间没有窗口成为 key | `[UI] 找不到 keyWindow，UI 延后` ×229；末段连续 40 次 / 20 秒 → `UI 启动重试 40 次仍无 keyWindow，放弃` |
| 设置页注入换掉的是 **UIKit** 的方法 | `[SettingsEntry] rowsOwner=UITableViewController cellOwner=UITableViewController selectOwner=(空) heightOwner=BDSettingViewController` |

`getSplashAdForColdLaunch` 的类型编码是 `v16@0:8` —— **返回 void，是"发起拉取"而不是"取结果"**。拦掉它 = 整条异步回调链永不开始。而"卡在启动图、不闪退、也不进入"正好等于 **SpringBoard 一直在显示启动快照（宿主主窗口从未提交第一帧）**。

## 2. 改了什么

1. **档 0 出厂**：`PFlag()`/`POn()` 改成"key 不存在 → NO"（旧语义是缺省全开）。26 个 `purify_*` 全部默认不生效。
2. **总开关不碰开屏**：`purify_master` 批量写开关时**排除** `purify_splash_ad`，避免"一把梭"把 App 弄回卡启动图。
3. **设置页注入出厂关**：`rea_settings_entry` 缺省 NO，`gREASettingsEntryOn` 初值改 NO。面板入口改由悬浮球承担。
4. **悬浮球挂载修复（P0-C）**：
   - `REAKeyWindow()`（要求 `isKeyWindow`）→ `REAAnyWindow()`（**只要可见窗口**，`isKeyWindow` 仅用于挑最上层）；
   - 窗口层级 `UIWindowLevelAlert + 1` → `UIWindowLevelNormal + 1`（不盖宿主弹窗、不改写"主窗口是否 key"）；
   - 挂完主动把 key 还给宿主；
   - 重试 40 次（20 秒）→ **6 次（3 秒）**，失败时打 `REAWindowSnapshot()` 现场快照而不是只写"放弃"。
5. **启动窗口探针**：`[Boot]` 在 0.05 / 0.30 / 1 / 2 / 5 / 10 / 20 秒各打一行窗口现场；≥5 秒仍无可见宿主窗口时直接打
   `[Boot] STUCK-LAUNCH`。

## 3. 安装

与 v12 完全一样的装法：**替换同一个 dylib**，plist / 包名 / 路径都不变。

- 产物：CI 的 `BluedHushREA-dylib`（release 变体）
- 文件名必须仍是 `BluedHushREA.dylib` + `BluedHushREA.plist`

## 4. 读日志：三种结局，三种结论

装好后**冷启一次**（杀进程 → 清 LiveContainer 缓存 → 等 3 秒 → 启动），看 `Documents/BluedHushREA.log`：

| 日志 | 结论 | 下一步 |
|---|---|---|
| `window attached level=1 hostKey=…` 出现，且屏幕上有悬浮球 | P0-C 修好；档 0 下 App 正常 | 进第 5 节，逐层开净化定位 |
| `[Boot] STUCK-LAUNCH: t=5.0s 仍无可见宿主窗口` | **L1（`getSplashAdForColdLaunch`）无关**——档 0 已经把它关了还卡，说明问题在广告 SDK 域（H-A2） | 抓 `.ips` + 看 `[Boot]` 那几行的窗口列表 |
| `[Purify] 档位：… L1(splash_ad)=off` 且 App 正常 | 档 0 干净 → 之前卡的就是净化 | 按第 5 节一层一层开 |

必看的三行：

```
[REA] build=v13.0-P0 …                    ← 确认装的是这一版
[Purify] 档位：… 当前生效 key=0/52，其中 L1(splash_ad)=off
[Boot] t=1.00 n=2,key=1 BluedWindow(lvl=0,hid=0,a=1.00,key=1) …
```

## 5. 逐层定位（档 0 之后）

面板里**一次只开一组**，每次开完冷启一次：

1. 先只开 `purify_banner` / `purify_mine_ad` / `purify_feed_ad` 这类"页面内广告位"——它们不碰启动路径；
2. 再开 `purify_float_layer` / `purify_block_call` 等交互拦截；
3. **`purify_splash_ad` 最后单独试**，开着它冷启一次：
   - 卡回启动图 → 确认 L1 有罪，该 key 从此保持 off，改用"展示层净化"重做（见 PLAN §3.1 的 L3/L4）；
   - 正常 → 说明 L1 只在特定广告源下发作（PLAN R13：CSJ / GDT 两套类名）。

## 6. 回滚

不需要改代码：`defaults` 里删掉对应 key 即回到档 0。要回到 v12 行为，直接装回 `dist/v12/BluedHushREA.dylib`。
